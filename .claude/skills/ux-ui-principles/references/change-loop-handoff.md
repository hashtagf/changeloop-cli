# Change Loop UX/UI working contract

Choose a design from the user's task and constraints. Preserve working product
conventions; do not impose a house aesthetic or claim usability from taste.
Read [experience workflow](experience-workflow.md) for research,
design, audit, improvement, and evidence limits. Read only the relevant topic
guides it names. [Upstream provenance](upstream.md) pins the imported
bundle and records the Change Loop adaptation.

## Working contract

1. Establish the actor, outcome, scope, content, devices, language, permissions,
   and failure consequences from supplied artifacts before asking decisions.
2. Separate observed behavior, assumptions, and missing measurements. Compare
   alternatives only when the interaction has consequential uncertainty.
3. Map entry, comprehension, action, feedback, recovery, and completion. Specify
   the critical loading, empty, denied, error, partial, and unknown states that
   apply; preserve work and avoid duplicate consequential submissions.
4. Make hierarchy, labels, navigation, responsive composition, keyboard/focus,
   and accessibility support the task. Distinguish standards and exceptions
   from platform conventions, heuristics, and project recommendations.
5. For layout choices, use the [layout index](../assets/layouts/index.md) and load
   only the relevant category plus [shared specification](../assets/layouts/specification.md).
   Blueprints and external references are starting points, not tested outcomes.
6. Tie findings to a location/state, user consequence, proposed repair, and
   observable verification. Prioritize blocked access and lost work before polish.
7. Use a runnable surface to exercise actions and resulting states when available.
   A screenshot supports composition findings, not keyboard, persistence,
   assistive-technology, conformance, or conversion claims.

## Handoffs

Record consequential choices and scenarios in the active compiled OpenSpec
agreement. Stay inside returned workspaces and allowed paths. Project providers
and the harness execute evidence, bind receipts, mark tasks, and own recovery
and lifecycle completion; a UX report is not proof or a second task ledger.

Use `frontend-design` for agreed visual implementation, `tailwind-design-system`
for shared token/component mechanics, and `ui-ux-pro-max` only when searchable
product/style/palette intelligence is needed. Use available design tools only
within the authorized deliverable. Do not assume Figma or another imported skill.

Follow the current harness action and exact resume route. This skill does not
grant Land, Git, publication, deployment, external messaging, or paid-research
authority. Report unverified checks as unknown rather than success.
